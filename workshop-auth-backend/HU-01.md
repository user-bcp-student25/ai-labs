# HU-01 — Proteger el token de autenticación frente al acceso desde JavaScript

## Origen

- **H-WEB-01** — Token de sesión en `localStorage`.
  - Evidencia: `web/src/app/services/auth.service.ts:27`
  - Evidencia: `web/src/app/services/auth.service.ts:32`

## Contexto

El flujo observado guarda el token de sesión en `localStorage`, donde puede ser leído por JavaScript del mismo origen. El hallazgo confirma este riesgo residual, pero no una explotación. Cambiarlo a `sessionStorage` no resuelve la exposición; una cookie `HttpOnly` requiere soporte del backend. El contrato observado de `POST /auth/login` debe conservarse.

## Ajustes necesarios

- Definir e implementar, coordinadamente con los clientes que usan la sesión, un mecanismo que impida que JavaScript del origen pueda leer el token.
- Mantener funcional el inicio de sesión y las solicitudes autenticadas dependientes de la sesión.
- No guardar ni incluir valores de tokens, secretos o credenciales en pruebas, registros o evidencia.

## Criterios de aceptacion

- Una prueba de integración de inicio de sesión verifica que, tras una respuesta exitosa de `POST /auth/login`, el token no queda disponible para JavaScript mediante `localStorage`, `sessionStorage` ni `document.cookie`.
- Una prueba de integración verifica que, después del inicio de sesión, una solicitud que requiere autenticación puede completarse correctamente sin exponer el token al código JavaScript del cliente.
- Una prueba de logout verifica que, al cerrar sesión, el cliente deja de poder realizar solicitudes autenticadas con esa sesión.
- Las pruebas verifican el comportamiento sin imprimir ni guardar el valor del token, secretos o credenciales.

## Evidencia esperada

- Pruebas automatizadas de inicio de sesión, acceso autenticado y logout, con resultados verificables.
- Evidencia de que las pruebas comprueban la no disponibilidad del token para JavaScript, sin registrar valores sensibles.
